# Forks & Pull Requests (Open Source and Team Workflow)

This is how **real teams and open-source projects collaborate**.

---

## Fork

A fork is a personal copy of someone else’s repository.

Used when:
- You don’t have write access
- You want to contribute safely

---

## Pull Request (PR)

A pull request is a request to merge changes.

PRs enable:
- Code reviews
- Automated testing
- Approval workflows

---

## Standard Workflow

1. Fork the repository
2. Clone your fork
3. Create a feature branch
4. Push changes
5. Open a Pull Request

---

## DevOps Importance

- PRs enforce quality gates
- CI/CD runs on PRs
- Production is protected

---

## Key Takeaway

No PR = no professional workflow.
